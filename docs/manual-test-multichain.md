# 人工测试：Arbitrum 支持与多签多链

对应提交：semi-app `38aa0bc`、`4db0764`，semi-backend `3d670f2`、`70ba07e`。
规则说明见 `semi-backend/docs/multisig.md`。

每一步都写了「预期」。与预期不符时，记下：账号、网络、钱包地址、交易 ID（详情页 URL 最后一段）、
页面报错原文、浏览器控制台里的红色错误。

---

## 0. 准备

### 账号

| 代号 | 用途 |
|---|---|
| A | 多签创建者，全程主操作 |
| B | 多签第二签名人 |
| C | 被加入 / 替换进来的新签名人 |

三个账号都要能登录、都设置好支付码，并记下各自的 handle 和个人钱包地址（设置页可复制）。
建议用三个不同浏览器（或无痕窗口）同时登录，省去反复切换。

### 资金

- OP、Arbitrum 由平台代付 gas，**不需要**准备 ETH。
- **主网不代付**。主网上的多签交易要由多签钱包自己付 gas，需要往多签地址转一点主网 ETH
  （一次 owner 变更在当前 gas 下约 0.001–0.005 ETH，按实时 gas 调整）。主网测试会花真钱，
  没有预算可以跳过带「主网」标记的步骤，其余步骤照做。

### 查链上状态

owner 和门槛以链上为准，页面上的数字只是后端镜像。核对方法：在区块浏览器打开多签地址 →
Contract → Read as Proxy → `getOwners` / `getThreshold`。

| 链 | 浏览器 |
|---|---|
| Optimism | https://optimistic.etherscan.io |
| Arbitrum One | https://arbiscan.io |
| Ethereum | https://etherscan.io |

还没部署的链上，地址页显示不是合约，这是正常的。

## 1. Arbitrum 基础（个人钱包）

**1.1 切换网络**
1. 登录 A，点右上角网络图标。
2. 预期：列表里有 **Arbitrum One**，带图标。
3. 选中 Arbitrum One。
4. 预期：提示「已切换到 Arbitrum One 网络」；刷新页面后仍是 Arbitrum One。

- [ ] 通过

**1.2 地址一致**
1. 分别在 OP 和 Arbitrum 下查看 A 的个人钱包地址。
2. 预期：两条链上地址**完全相同**。

- [ ] 通过

**1.3 余额与转账（代付）**
1. 在 Arbitrum 下，从外部往 A 的地址转一点 ETH（例如 0.0005）。
2. 预期：几十秒内首页余额更新。
3. 从 A 向 B 转 0.0001 ETH。
4. 预期：转账成功；手续费由平台代付，A 的余额只减少转账金额；如果这是 A 在 Arbitrum 上的第一笔交易，
   浏览器上 A 的地址变成合约。
5. 在交易记录里能看到这笔转账。

- [ ] 通过

**1.4 发币入口**
1. 在 Arbitrum 下进入发行代币页面，填写后提交。
2. 预期：提示「Arbitrum One 暂不支持发行代币」，**不会**弹出支付码或发出交易。

- [ ] 通过

## 3. 老钱包自动补链

针对上线前就存在的 OP 多签钱包（生产上共 6 个）。

**3.1 补链**
1. 用某个老钱包的 owner 登录，在 OP 下打开钱包列表（这一步会在后台补链）。
2. 切到 Arbitrum One，再打开钱包列表。
3. 预期：多数老钱包在 Arbitrum 上也出现，地址与 OP 相同。
4. 进入该钱包的成员页。预期：显示的是钱包**创建时**的成员和门槛（Arbitrum 上还没部署，生效的是初始配置），
   不一定等于 OP 上现在的成员。

- [ ] 通过

**3.2 改过成员的老钱包**
钱包 `3mnvjcz423wzl`（OP 上现在 1 个成员）和 `3mo66fsikdihd`（OP 上现在 5 个成员）在 OP 上改过成员。
1. 用它们**创建时就在**的成员登录，切到 Arbitrum。
2. 预期：能看到钱包，成员为创建时的那一组。
3. 用**后来才加入**的成员登录，切到 Arbitrum。
4. 预期：看**不到**这个钱包（他在 Arbitrum 上还不是 owner），切过去会回到个人钱包。这是预期行为。
5. 如果创建时的成员在 Arbitrum 上也看不到：打开控制台，找 `initial config does not predict the Safe address`
   日志——表示后端还原的初始配置对不上，这个钱包不会补链，记录下来。

- [ ] 通过

## 4. 单链交易（不分组）

使用第 2 步的 `S1`。

**4.1 Arbitrum 上首笔转账（顺带部署）**
1. 往 `S1` 在 Arbitrum 上转 0.0005 ETH。
2. A 切到 Arbitrum，在 `S1` 里发起转账：向 C 转 0.0001 ETH。
3. 预期：只生成**一笔**交易，详情页**没有**「所有链」卡片。
4. A 签名，B 签名，任一人执行。
5. 预期：执行成功；浏览器上 `S1` 在 Arbitrum 上变成合约；C 收到 0.0001 ETH；gas 由平台代付。
6. 切到 OP 查看 `S1` 的队列。预期：没有这笔交易。

- [ ] 通过

## 5. 成员变更：一次发到所有链

此时 `S1` 的状态：OP 未部署、Arbitrum 已部署、主网未部署——正好覆盖「已部署 / 未部署混合」。

**5.1 发起加成员**
1. A 在 OP 下进入 `S1` 成员页，添加 C，门槛保持 2。
2. 预期：提示「已在所有链上发起提案」，跳转到 **OP** 上的那笔交易。
3. 预期：详情页有「所有链」卡片，列出 OP、Arbitrum One、Ethereum 三行，状态都是待签名。
4. 点 Arbitrum 那一行的「查看」。预期：打开 Arbitrum 上的那笔交易，内容相同（添加 C，门槛 2）。

- [ ] 通过

**5.2 重复发起被拒**
1. 在 5.1 的交易都未完成时，A 再次添加 C。
2. 预期：报错，提示同一变更已在进行（`already pending`），不会生成新交易。

- [ ] 通过

**5.3 为所有链签名**
1. A 在任意一条链的详情页点「为所有链签名」，输入一次支付码。
2. 预期：只输入**一次**支付码；提示「已签名：Optimism、Arbitrum One、Ethereum」。
3. B 登录，同样操作。
4. 预期：三条链状态都变成「待执行」。

- [ ] 通过

**5.4 执行所有就绪的链（主网余额不足）**
先**不要**往主网的 `S1` 转 ETH。
1. A 点「执行所有就绪的链」，输入支付码。
2. 预期：OP、Arbitrum 执行成功；Ethereum 报「不代付 gas，数字身份在该链上的 ETH 余额不足以支付手续费」；
   主网那笔**仍是待执行**（不是失败）。
3. 浏览器核对：OP 上 `S1` 变成合约，`getOwners` 含 A、B、C，`getThreshold` = 2；Arbitrum 同样含 A、B、C。
4. 页面上 OP、Arbitrum 的成员页显示 3 人。Ethereum 的成员页仍显示 A、B。

- [ ] 通过

**5.5 主网执行**（主网）
1. 往 `S1` 在主网上转足够的 ETH。
2. 回到该交易详情页，点「执行所有就绪的链」。
3. 预期：Ethereum 执行成功；浏览器上 `S1` 在主网变成合约，owner 含 A、B、C；ETH 余额扣掉了 gas。

- [ ] 通过（或：跳过主网）

**5.6 新成员可见性**
1. C 登录，依次切到 OP、Arbitrum、Ethereum，打开钱包列表。
2. 预期：已执行的链上都能看到 `S1`；如果跳过了 5.5，Ethereum 上看不到。

- [ ] 通过

## 6. 删除 / 替换 / 改门槛

继续用 `S1`（OP、Arbitrum 上成员 A、B、C）。

**6.1 删除成员（prevOwner 按链计算）**
1. 新建一个多签 `S2`：成员 A、B、C，门槛 2，**不做任何交易**（三条链都未部署）。
2. A 在 Arbitrum 下，从 `S2` 删除 B，新门槛 1。
3. A、B（或 A、C）为所有链签名，执行 OP 和 Arbitrum。
4. 预期：两条链都执行成功（不是「交易已上链但调用失败」）；浏览器上 `getOwners` 只剩 A、C，`getThreshold` = 1。
   这一步验证的是未部署链上 prevOwner 的推算。

- [ ] 通过

**6.2 替换成员**
1. 在 `S1` 上把 C 替换成 B 以外的另一个账号（或在 `S2` 上把 C 替换成 B）。
2. 签名并执行所有就绪的链。
3. 预期：各链 `getOwners` 中旧成员被替换为新成员。

- [ ] 通过

**6.3 改门槛**
1. 在 `S1` 上把门槛从 2 改成 3。
2. 预期：生成分组交易，签名执行后各链 `getThreshold` = 3。
3. 再次发起「改成 3」。预期：不会生成交易（门槛已经是 3，变更不适用）。

- [ ] 通过

## 7. 撤回与失败

**7.1 撤回联动**
1. A 在 `S1` 上发起一次成员变更（例如门槛改回 2）。
2. B 只在 **OP** 那一笔上签名（从 OP 详情页点普通的签名按钮，不点「为所有链签名」）。
3. A 打开 **Arbitrum** 那一笔，点「撤回」。
4. 预期：Arbitrum、Ethereum 两笔变成已撤回；OP 那笔因为已有签名，**仍是待签名**。

- [ ] 通过

**7.2 部分链失败不影响其他链**
5.4 已覆盖（主网余额不足时 OP、Arbitrum 照常执行）。

- [ ] 通过
